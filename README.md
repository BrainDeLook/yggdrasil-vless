# Yggdrasil + VLESS: установка на VPS

Установщик `install-ygg-vless.sh` для **Debian 12+ / Ubuntu 22.04+**, архитектуры **amd64 / arm64**, с systemd и доступным `/dev/net/tun`. Запускать на VPS с выходом в интернет и правами root. Публичный IPv6, домен и сертификат не нужны, но IPv6 внутри ОС должен быть включён.

Схема: клиент → сеть Yggdrasil → VLESS на VPS → интернет через IPv4 VPS.

## Запуск

Выполните на VPS по SSH от root:

```bash
curl -fsSL https://raw.githubusercontent.com/BrainDeLook/yggdrasil-vless/main/install.sh -o /tmp/ygg-vless-install.sh && bash /tmp/ygg-vless-install.sh
```

Если `curl` ещё не установлен:

```bash
apt-get update && apt-get install -y curl ca-certificates
```

Загрузчик скачает установщик релиза `v1.0.0` и проверит зафиксированный SHA256 до его запуска. Исходники доступны для просмотра в этом репозитории.

После успешной проверки скрипт выведет готовую ссылку:

```text
vless://UUID@[YGGDRASIL_IPV6]:1488?encryption=none&security=none&type=tcp#Yggdrasil-VLESS
```

Импортируйте всю строку в раздел подключений Тахиона или VLESS-клиент. Telegram сам VLESS не принимает: для него нужен Тахион или отдельный клиент, который принимает VLESS и проксирует трафик Telegram.

## Что делает скрипт

- Устанавливает зависимости через APT.
- При отсутствии Yggdrasil устанавливает официальный пакет **0.5.14** с проверкой SHA256. Существующую версию **0.5.x** сохраняет.
- Сохраняет приватный ключ, адрес, существующих пиров и остальные параметры Yggdrasil. Делает резервную копию конфигурации.
- Если пиров нет, добавляет три публичных TLS-пира из официального каталога. Дожидается адреса интерфейса и хотя бы одного подключённого пира.
- Устанавливает отдельный **sing-box 1.14.3** в `/opt/ygg-vless/` с проверкой SHA256. Не меняет существующую службу/config sing-box.
- Создаёт UUID, VLESS-конфигурацию и службу `ygg-vless` от отдельного системного пользователя.
- VLESS слушает только адрес Yggdrasil. TLS/Reality поверх VLESS не используются: трафик между узлами уже шифрует Yggdrasil. UUID из ссылки является секретом доступа.
- Разрешает домены на стороне VPS в IPv4, поэтому клиент может передавать доменные назначения.
- Для активного UFW/firewalld добавляет узкое разрешение TCP к этому адресу/порту. Не включает firewall и не сбрасывает его правила.
- Включает автозапуск обоих сервисов и выполняет HTTPS-запрос через временный SOCKS-клиент → VLESS → сервер → интернет. Успех — HTTP 204.

При повторном запуске UUID и выбранный порт сохраняются. Файл `/etc/yggdrasil.conf` преобразуется в JSON без замены идентичности. Сервис Yggdrasil перезапускается, поэтому его соединения кратковременно прервутся. Резервные копии находятся в `/etc/ygg-vless/backups/`.

## Условие для клиента в локальной сети

Недостаточно установить Yggdrasil на любом одном устройстве LAN. **Именно устройство с VLESS-клиентом должно достигать адреса сервера `200::/7`.**

Варианты:

1. Yggdrasil работает на самом устройстве с VLESS-клиентом.
2. Yggdrasil работает на роутере, а LAN-клиент получил IPv6-адрес из выделенной Yggdrasil подсети роутера `300::/64` и маршрут к `200::/7` через него. Также должны быть разрешены forwarding и обратный трафик. Внешний IPv6 провайдера не обязателен.

На OpenWrt проверяйте с роутера, на остальных устройствах — с самого устройства:

```sh
ping -6 АДРЕС_YGGDRASIL_СЕРВЕРА
```

Windows:

```powershell
ping -6 АДРЕС_YGGDRASIL_СЕРВЕРА
Test-NetConnection -ComputerName 'АДРЕС_YGGDRASIL_СЕРВЕРА' -Port 1488
```

Если клиент использует TUN/VPN, соединение к адресу VLESS-сервера должно идти системным маршрутом через Yggdrasil, не попадать обратно в этот же VLESS-туннель. Соединения самого Yggdrasil к публичным пирам также должны оставаться рабочими.

Установщик на VPS не меняет настройки домашнего роутера и LAN. Успешный локальный тест сервера не доказывает доступность с удалённого устройства: после импорта ссылки нужно проверить запрос уже через клиент.

## Управление

```bash
sudo ygg-vless --show-link
sudo ygg-vless --status
sudo ygg-vless --test
sudo journalctl -u ygg-vless -f
sudo journalctl -u yggdrasil -n 50 --no-pager
sudo systemctl restart ygg-vless
```

Ссылка: `/etc/ygg-vless/client.txt` (доступ root).

Готовый sing-box outbound для ручного импорта JSON: `/etc/ygg-vless/client-outbound.json`.

UUID/порт/адрес: `/etc/ygg-vless/settings.json`.

Конфигурация сервера: `/etc/ygg-vless/server.json`.

Другой порт:

```bash
sudo ygg-vless --port 2443
```

Свой список пиров (явно заменяет текущий список `Peers`, но не меняет ключ):

```bash
sudo ygg-vless \
  --peer 'tls://ПИР_1:ПОРТ' \
  --peer 'tls://ПИР_2:ПОРТ'
```

## Firewall и особенности VPS

Скрипт рассчитан на обычный VPS. В контейнере провайдер должен выдать TUN и нужные права. Если IPv6 отключён sysctl, установщик остановится с сообщением; публичный IPv6 при этом покупать/включать у провайдера не требуется.

Для UFW требуется `IPV6=yes`. При активном нестандартном nftables/ip6tables установщик остановится, не изменяя эти правила. Нужно добавить разрешение IPv6 TCP с интерфейса Yggdrasil к его адресу на выбранный порт, затем запустить с `--firewall-ready`. Этот флаг только подтверждает, что вы уже настроили свой firewall; сам ничего не разрешает. Правила должны сохраняться после перезагрузки. Нестандартный OUTPUT firewall также должен пропускать пиров, DNS и выход прокси в интернет.

Публичный VLESS-порт в панели VPS открывать не требуется: VLESS слушает внутренний адрес Yggdrasil. Однако VPS должен иметь исходящий доступ к публичным пирам. Для пиров по умолчанию используются TLS TCP 443, 44442 и 7992; при ограничениях их можно заменить своими.

Общедоступные пиры могут менять адреса/доступность. Установщик проверяет фактическое подключение и сообщает об ошибке, если нет ни одного живого пира. Он не объявляет установку успешной при провале проверки.

Если есть другие службы на Yggdrasil-интерфейсе, их доступность определяется вашим существующим firewall. Существующие Listen/MulticastInterfaces Yggdrasil сохраняются.

## Проверки этой поставки

- Синтаксис скрипта проверен настоящим `bash -n`.
- Все встроенные Python-программы компилируются.
- Проверены сохранение ключа Yggdrasil/пиров, явная замена пиров, сохранение UUID, изменение порта и генерация ссылки с IPv6 в скобках.
- Производственный конфиг принят командой `sing-box check` версии 1.14.3.
- На Windows выполнен настоящий локальный обмен SOCKS5 с доменным назначением → VLESS по IPv6 → DNS на сервере → HTTP по IPv4. Проверено отклонение неверного UUID.
- Полная установка APT/systemd, TUN, UFW/firewalld и связь между двумя удалёнными узлами Yggdrasil ещё не проверялись на реальном Linux VPS. Скрипт выполняет свои проверки при установке; для окончательного подтверждения нужен тест с вашего роутера/клиента.
